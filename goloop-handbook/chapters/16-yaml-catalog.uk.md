# 16. Каталог, який ведуть руками

**Задача.** Сервіс читає не один вид YAML, і ці види не однакові. Один файл -
курований каталог: його редагує хтось із команди, його переглядають на рев'ю, і
від помилки в ньому чекають, що її спіймають. Інший приходить завантаженням,
його написав інструмент, якого команда не контролює, у форматі, з якого наша
структура є лише підмножиною. Читати обидва одним викликом - це спосіб тихо
загубити одруківку куратора й водночас відхилити імпорт користувача через
нешкідливий зайвий ключ.

**Модулі.** [`yaml`](https://github.com/goloop/yaml) читає конфігураційну
підмножину YAML із відповідністю як в `encoding/json` і приймає опції, які
кажуть, на який саме з цих двох файлів він дивиться.

**Рецепт.** [`recipes/016-yaml-catalog`](../recipes/016-yaml-catalog/)

## Строгість - це властивість автора

Каталог читається строго:

```go
err := yaml.Unmarshal(data, &c,
	yaml.WithStrict(),       // невідомий ключ - це одруківка
	yaml.WithExpandStrict(), // токен приходить із середовища
)
```

Завантаження - ні:

```go
err := yaml.Unmarshal(data, &m) // невідомий ключ - поле, яке нам ще не потрібне
```

Обидва правильні, і кожен був би неправильним на місці іншого. `WithStrict`
питає: «чи мав автор на увазі щось, чого ця програма не знає?» - слушне питання
про файл, який написав колега, і нечемне про файл, який видав чужий інструмент.
Дефолту, правильного для обох, не існує - тому це рішення на місці виклику, а не
налаштування пакета.

Зверніть увагу, чого завантаження **не** отримує: розкриття змінних. Файл прийшов
іззовні, і дозволяти йому читати середовище цього процесу - не можливість, а
діра.

## Що може сказати тег

Два завантажувачі в продакшні виростили однаковий блок нагорі:

```go
if fm.Title == "" || fm.Slug == "" || fm.Language == "" || fm.Category == "" {
	return draft{}, fmt.Errorf("%s: title, slug, language and category are all required", path)
}
```

Він працює - і не каже авторові майже нічого: яке саме поле і де. Натомість це
може сказати структура, один раз, там, де поле оголошене:

```go
type Source struct {
	Slug     string        `yaml:"slug,required"`
	Endpoint url.URL       `yaml:"endpoint,required"`
	Timeout  time.Duration `yaml:"timeout" def:"30s"`
	Quality  int           `yaml:"quality" def:"80"`
	Enabled  bool          `yaml:"enabled" def:"true"`
}
```

```
catalog: line 3: incomplete: main.Source: key "slug" is required and the
document does not set it
```

`def` - друга половина. Куратор не має виписувати таймаут, з яким і так згоден, а
завантажувач не має тягнути `if s.Timeout == 0 { s.Timeout = 30 * time.Second }`,
щоб це надолужити.

Типи теж працюють. `timeout: 30s` є `time.Duration`, бо таким є поле, а
`timeout: 30` відхиляється, замість читатися як тридцять наносекунд.
`endpoint: https://example.com/feed.xml` є `url.URL`, розібраним при
завантаженні, а не при першому запиті, який ним скористається.

## Три відповіді, які варто знати наперед

**Merge-ключ рахується присутнім.** Куратори перевикористовують блоки - і мають
це робити:

```yaml
defaults: &defaults
  timeout: 45s
sources:
  - <<: *defaults
    slug: weekly
```

Присутність визначається після розкриття merge, тож `required` бачить те саме,
що й декодер. Якби ні, файл, який читається бездоганно, не завантажувався б.

**Тримач анкора - такий самий ключ, як усі.** У YAML немає поняття блоку, який
існує лише щоб на нього посилалися, тож під `WithStrict` `defaults:` вище треба
оголосити:

```go
Defaults map[string]any `yaml:"defaults,omitempty"`
```

Його ніхто не читає. Він там, бо інакше першому кураторові, який потягнеться по
анкор, скажуть, що його файл неправильний.

**Явний `null` не є відсутністю.**

```yaml
quality: null   # з def:"80" дасть 0, а не 80
```

Написати `null` - це рішення. Замовчування, яке його скасовує, скасовувало б
рішення людини, що писала файл, а `required` задовольняється наявністю ключа, бо
питає, чи автор звернувся до налаштування, а не чи значення непорожнє.

## Не рвіть ланцюжок помилок

Завантажувач хоче додати контекст - і очевидний спосіб викидає те, до чого він
цей контекст додає:

```go
return nil, fmt.Errorf("catalog%s", describe(err)) // причина стала рядком
```

Після цього `errors.Is(err, yaml.ErrRequired)` хибний, а той, хто хотів
відрізнити «файл неповний» від «файл неправильний», лишається зі звірянням
тексту повідомлення. Маленький тип зберігає і те, і те:

```go
type LoadError struct {
	What string
	Err  error
}

func (e *LoadError) Error() string { return e.What + describe(e.Err) }
func (e *LoadError) Unwrap() error { return e.Err }
```

Тепер повідомлення й далі несе номер рядка, а `errors.Is(err,
yaml.ErrRequired)` і далі відповідає.

## Записати назад

Експорт - це файл, який чіпляють до тікета або комітять у гілку, тож токени, які
на вході прийшли з середовища, не йдуть із ним назовні:

```go
out := *c
out.Sources = slices.Clone(c.Sources)
for i := range out.Sources {
	out.Sources[i].Token = "" // omitempty тоді прибирає ключ узагалі
}
return yaml.Marshal(out)
```

Вивід детермінований - ключі мап відсортовані, поля структур у порядку
оголошення, - тож згенерований каталог не смітить у version control, а
`time.Duration` виходить назад як `45s`, а не числом, яке ніхто не прочитає.

## Висновки

- Вирішуйте строгість для кожного документа окремо, за тим, хто його написав:
  `WithStrict` для файлу, який веде колега, звичайний `Unmarshal` для формату,
  який вам не належить.
- Не розкривайте середовище у файл, що прийшов іззовні.
- `,required` і `def` кажуть у структурі те, що завантажувачі інакше кажуть
  у блоках `if`, і кажуть це з номером рядка.
- Присутність визначається після merge-ключів; явний `null` - це рішення, а не
  пропуск.
- Загортайте помилки декодування типом із `Unwrap`, інакше `errors.Is` перестає
  працювати рядком нижче.
- `Validate` нікуди не подівся - для правил, що охоплюють більше ніж одне поле.

Це завершує Частину IV. Ви взяли модулі Частин I-III і надали їм форму, якою їх
формує продакшн: падати рано, відмовляти чесно, резолвити справжнього клієнта,
питати, що вміє провайдер, відповідати словником, на який фронтенд може діяти, і
читати файл так, як його мав на увазі автор.
